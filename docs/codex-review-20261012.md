## 定位判断

用户要的是将现有感知数据处理成下游机器人/AI 可消费的数据软件。
现有 RGB-D 米制点云链路与 LeRobot 视频/状态/动作读取符合这个目标。
总纲写了 FR-12，但没有给统一数据服务安排实际里程碑，同时又称报告是唯一研发部分，
存在偏成第三方质检聚合器的风险。本次把 FR-12 安排为下一轮优先任务，
报告作为并行诊断；保留未来模型、空间与边缘接口，不立刻扩张实现。

当前主要是离线软件；尚无在线实时传感器接入或机器人控制。
PushT 是任务相关的二维视觉/状态/动作数据，不提供米制深度、空间标定或世界地图。
商业付费需求和更广泛通用性尚未由这些测试证明。

## 发现与实际修复

| 问题 | 修复与证据 |
|---|---|
| 首个 Parquet schema 代表所有文件，缺流却记满 episode | schema union；逐文件分批扫描数值，缺流计数为 0；两数据文件/跨 chunk 回归 |
| 列全 null、NaN、错误 shape 仍 DELIVERED | 数值契约校验；可选坏流 UNAVAILABLE，其他流继续读，不填造值 |
| 缺 frame_index 静默制造序号 | 必需索引缺失明确报错；校验行数、帧序、时间和全局边界 |
| 文件存在/预览/完整解码混称 DELIVERED | PRESENT/PARTIAL/DELIVERED 分开，并返回验证依据和帧数 |
| 损坏视频被当作文件缺失；部分解码没有数量证据 | 存在但解码失败为 UNAVAILABLE；部分解码返回实际 read_frames |
| seek 返回值被忽略，片段越界或不同 fps 可错位 | CFR 顺序 ordinal 定位；校验起止边界、解码 fps，多速率需要显式映射，当前拒绝 |
| 版本前缀误接受 v30；视频元数据 null 崩溃 | 收紧版本格式；null 视频片段作为缺失引用；必需元数据报领域异常 |
| 视频错 1–2 帧也可通过灰度容差 24 | 容差收紧为 4，另加无损 mock 精确帧号、两视频 chunk 回归 |
| 元数据模板可读取数据目录外的文件 | 路径 containment 校验，不读取目录外 payload |
| 文档声明已实现清晰度/黑帧，范围偏报告 | 更正未实现状态；FR-12 优先；原始只读与派生处理边界写清 |

delivery 的状态属于读取层，不能与 Findings 的 NOT_DELIVERED/NOT_RUN/
NOT_DETECTED/DETECTED 混用。未来映射要记录检查覆盖，不能凭一个状态猜测。
数字流清单的 `numeric_values` 表示逐批 shape/类型/有限性与长度覆盖；
不是完整的业务质量检查或下游策略有效性证明。
